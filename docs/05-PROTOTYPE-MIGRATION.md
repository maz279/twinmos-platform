# 05 — Prototype → Production Migration Guide

The prototype (Features/prototype, 28 pages) is the UI/UX contract. This is a port, not a redesign.

## Port method (per page)
1. Take the prototype's rendered HTML (build.py output) as the reference render.
2. Create `apps/web/src/pages/<route>.astro`: copy the `<main>` markup, wrap in `Base.astro` (which owns header/footer/mega menus/drawer/search overlay — ported once from pb_templates).
3. Replace server-injected helpers (brand logo spans, inline SVG icons, hashed asset URLs) with Astro partials/components.
4. Move page-specific JS init into a `<script>` tag (Astro bundles and scopes it) — the vanilla behaviors port nearly verbatim.
5. Data: replace `data.js` reads with typed build-time queries (packages/db or JSON loaders generated by the corpus importer in tooling/).
6. Parity gate: Playwright screenshot-diff vs captured prototype screenshots at 390/768/1280 — max ~2% pixel diff outside font/AVIF variance.

## Shared components to port once
Header + 6 mega menus + drawer · search overlay · footer · breadcrumb · page-hero · card grids (g2/g3) · chips/badges · tabs + accordions · steps · note-box · trust-band · form machinery (fg/req/err) · compare tray · toasts · cookie bar (real consent manager in P2) · hero slider.

## Islands (interactive ports)
Shop grid + facets · PDP gallery/variants · Compare tray (localStorage now, server list later) · Compatibility finder · RMA tracker (demo → live API) · Search overlay (→ Pagefind UI) · Forms (client-side validate with packages/shared Zod → POST API).

## Asset port
`main.css` → `src/styles/main.css` verbatim (tokens unchanged; new components use the same variables). Baked hero WEBPs + product imagery → `src/assets` (Sharp takes over variants; Pillow scripts stay in tooling/ for regenerating bakes). Service worker, hashed URLs, manifest: Astro/Vite provide equivalents natively.

## Definition of "migrated"
Page renders from the Astro build; passes the parity gate; Lighthouse ≥ 90 perf / ≥ 95 a11y; 0 axe criticals; all internal links resolve; JSON-LD present; strings marked for i18n extraction.
