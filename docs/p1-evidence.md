## 2. Gate results

### Gate 1 — Visual parity (≥98% identical pixels vs prototype @ 390/768/1280)

Protocol: headless Chrome `--headless=new --force-prefers-reduced-motion --virtual-time-budget=25000 --run-all-compositor-stages-before-draw`, fresh profile per shot, PIL ImageChops per-channel diff, tolerance ≤8, **retry up to 3× per pair** (auto-advancing carousels make a single capture phase-luck-dependent; controlled pairs prove parity).

Results (`_p1/parity/final_parity.tsv`, 87 pairs = 29 targets × 3 widths):

- **73/87 pairs ≥ 98%** (typical 98.1–100.0; min pass 98.06)
- **14 pairs in 96.5–98.0**, all deterministic (stable across 3 retries), all on text-glyph-dense pages, all root-caused as **WCAG-AA contrast corrections** (see §3): news (3 widths 96.5–97.5), technology (390/768 96.7/97.5), learn hub (7 pairs 96.9–98.0), article@390 97.0, product@390 97.8
- Pages with animated content verified via controlled pairs: gaming A-vs-A control 90.5 (prototype self-nondeterminism) vs A-vs-B 99.8/99.9; index@768 recovered 99.59 with retry

**Parity↔a11y conflict (documented decision):** the prototype itself measures **a11y 91–94** (Lighthouse color-contrast: 3–75 failing nodes/page — measured on localhost:8123, `_p1/lh/PROTO_*.json`). Byte-identical pixels would inherit those failures and break the ≥95 a11y gate. The port resolves in favour of WCAG AA: recolouring only text glyphs (never solid fills) costs 0.2–1.5% parity on the affected pages. P2 (semantic components) eliminates the debt.

### Gate 2 — Zero JS errors + hydration proof

Protocol: `--dump-dom --virtual-time-budget=25000` on all 29 targets; prototype `app.js` sets `body[data-js-error]` on any same-origin error.

- `data-js-error` present on **0/29** pages (`_p1/js_results.txt`)
- Hydration proven via JS-only artifacts: shop 12 `data-catchip` chips + 39 `pcard-body`; careers 73 `<option>`; gaming counters rendered; shim artifacts (breadcrumb `<ul>`, `data-dims` on imgs) present on all applicable pages

### Gate 3 — axe-core, zero criticals

Protocol: axe-core 4.x via `__audit/axe2.html` iframe harness (axe runs in the audited window's own context; negative control `bad.html` correctly reports criticals), headless Chrome, virtual-time budget; harness excluded from git and production builds (`tooling/restore_audit_harness.sh` re-installs it for re-runs).

- **29/29 pages: zero critical violations** (`_p1/axe_results.txt`)
- Remaining (non-blocking, prototype-inherited): 14 serious (contrast residue), 56 moderate (heading-order, region) — tracked for P2

### Gate 4 — Lighthouse (mobile, default throttling; `_p1/lh/Z_*.json`)

All 29 targets — **perf ≥ 90 · a11y ≥ 95 · best-practices ≥ 96 · SEO = 100** (404 SEO 69 = intentional `noindex`):

| | perf | a11y | bp | seo |
|---|---|---|---|---|
| min | 90 (product deep link) | 95 (9 pages) | 96 (5 pages) | 100 (28; 404=69 by design) |
| max | 100 (7 pages) | 100 (careers) | 100 | 100 |

Perf work behind the numbers: deferred app boot (prototype index 75 → port 91–97); PDP/article `empty-state` CLS reserves (product CLS 0.86→0.13, article 0.51→0.001); `#searchMount:empty` reserve (search CLS 0.16→0.025 while keeping final pixels identical); img-dims map; PDP hero preload. Residual product CLS 0.13 + LCP band is the client-rendered-PDP architecture — fixed properly by P2 static per-product routes.

## 3. Accessibility fixes (port-only layer)

All in `a11y-overrides.css` (glyph recolours, dark-theme rules untouched by specificity) and `a11y.js` (attribute-only DOM fixes, change-guarded, rAF-coalesced observer):

- Contrast: accent-deep text #0082B3 (4.34:1) → #00729C (5.4:1) on `.eyebrow/.link-arrow/.cat-cta/.pcard-cat/.brand-chip span/button.tab/.variant/.note-box a/.learn-band a` (+`!important` vs one inline-styled link); muted #5E7691 → #4E6579; `.btn-accent` white→navy #0A2540 text (fill untouched); cookie-bar links → #4FC3F7; `.sbg-hdd` → #CBD5E1; `.b-neon p` → #AFC4D6; underlines on in-text links
- Semantics: form labels bound (`for`/`id` + aria-label) on all app.js-generated forms; breadcrumb `<li>`s wrapped in `<ul>` (invalid `role="list"` on `<nav>` avoided after it itself flagged); invalid `role="tablist"` removed from filter chips; `role="tablist"` added to orphaned tab pill rows; `role="group"` removed from hero slides; `alt=""` on injected decorative imgs; icon-only buttons named
- CLS: width/height attrs from build-time intrinsic-size map; empty-state reserves on PDP/article; `:empty` reserve on search mount

## 4. Reproducing the gates

```bash
cd apps/web
npm run build          # astro build + pagefind
npx astro preview &    # localhost:4321 — RESTART after every build (in-memory file cache!)
node ../../"Corporate website development for TwinMOS"/Features/prototype/serve.js &  # :8123
# gate 1: _p1/parity protocol (see this doc §2; scripts ran in the browser-use kernel)
bash ../../_p1/js_sweep.sh          # gate 2
bash tooling/restore_audit_harness.sh && npx astro build && bash _p1/axe_sweep.sh && rm -rf public/__audit  # gate 3
npx lighthouse http://localhost:4321/index.html --chrome-flags="--headless=new" # gate 4 (per page)
```

Gotchas baked into this doc: preview server caches dist in memory (restart after build); browser-use tab throttles onload callbacks (use the subprocess harness); carousels need parity retries; every fixed reserve on a client-rendered mount must be measured, not assumed.
