# Architecture Decision Records (D-1 through D-12 & D-9a)

**Status:** Signed off & Accepted · **Date:** 2026-10-12 · **Standard:** ISO/IEC 42010

---

## D-1: Extend the Existing Custom CMS
- **Decision:** Extend the existing custom CMS (Hono API, React Admin SPA, Better Auth RBAC, and Postgres audit log). Do not migrate to Strapi v5.
- **Context & Evidence:** The API already hosts over 129 route handlers, 15 administrative modules, full RBAC, revision tracking, and an immutable audit log with 331 passing automated tests. Migrating to an off-the-shelf headless CMS would discard tested business logic without addressing edge or accessibility requirements.
- **Consequences:** The team maintains complete ownership of schemas, RBAC barriers, and client integration contracts.

---

## D-2: Docker Compose on a Single VM
- **Decision:** Deploy using Docker Compose on a single VM (PostgreSQL 18, migration job, API, web SSR, edge Nginx) with container parity across dev, CI, and production.
- **Context & Evidence:** Lab testing in `compose_lab/` verified container isolation, automatic health checks, internal network routing (API port unpublished to host), restart resilience, and idempotent migrations.
- **Consequences:** Eliminates snowflake configuration differences between development workstations and production infrastructure.

---

## D-3: Server-Side Rendering on Request with Astro 7 & Multi-Layer Caching
- **Status:** Accepted, not implemented (Target: Phase B)
- **Decision:** Transition public site rendering to server-side rendering on request using Astro 7 (`@astrojs/node` standalone) with three cache tiers: in-memory route cache (tag-invalidated on publish), 5s Nginx micro-cache (`X-Accel-Expires`), and stale-on-error fallback.
- **Context & Evidence:** Tested in lab `astro_ssr_spike/` (R1): publish-to-fresh page latency is under 500ms; draft previews never leak to anonymous visitors; cached pages survive upstream API restarts. Static-only rebuilds cannot support dynamic parameterized routes (`/products/<slug>`, etc.) or real-time previews.

---

## D-4: Read-Only Delivery API inside Existing Hono App
- **Decision:** Implement a read-only Delivery API inside the existing Hono service accessible exclusively over the private Docker network by the Astro web service.
- **Context & Evidence:** Astro never directly connects to PostgreSQL. Encapsulating content queries within the Delivery API enforces a single choke point for publication status, draft token verification, and payload shaping.

---

## D-5: Clean Canonical URLs with 1:1 301 Redirects
- **Decision:** Establish clean URLs (`/about`, `/products/<slug>`, `/learn/<slug>`, etc.) with self-referencing canonical tags, plus permanent 1:1 301 redirects from all prototype `.html` and `?id=` URLs as well as legacy site paths (maintained for ≥1 year).
- **Context & Evidence:** Google Search Central documentation mandates that canonical URLs represent authoritative endpoints rather than IDs, and that site migrations preserve ranking equity through persistent 1:1 redirects rather than catch-all redirects.

---

## D-6: Content Model: Page Entity Composed of 25 Block Types & 6 Core Entities
- **Decision:** Model public site pages through a unified `page` entity composed of 25 typed block schemas and 6 domain entities (products, categories, articles, glossary, offices, policies).
- **Context & Evidence:** Component inventory cataloged 230 UI components across 31 types, requiring formal schema modeling to eliminate hardcoded page markup.

---

## D-7: Search via PostgreSQL Full-Text Search
- **Status:** Accepted, not implemented (Target: Phase D)
- **Decision:** Implement search using PostgreSQL native full-text search (`tsvector` per locale, GIN indexes) queried through the Delivery API. Decommission Pagefind upon completion of SSR transition.
- **Context & Evidence:** Pagefind cannot index dynamic server-rendered pages during client requests. PostgreSQL FTS requires zero external indexing infrastructure, supports multilingual lexemes, and prevents draft leakage.

---

## D-8: Localisation Model & Clean Route Fallbacks
- **Decision:** Localized content variants are bound by `translation_group`. Default English URLs remain unprefixed; other languages use `/<locale>/...`. An untranslated page performs a 301 redirect to its English canonical URL rather than serving English body text under a foreign `lang` tag.
- **Context & Evidence:** W3C and Google guidelines require reciprocal `hreflang` tags and strict language attribute compliance. Serving mismatched text corrupts indexing and screen reader pronunciation.

---

## D-9: Comprehensive Security Baseline
- **Decision:** Enforce invitation-only account creation; default all accounts to rank-0 `member`; disable Better Auth default `/admin/*` management routes; mandate MFA for admin roles; enforce trusted real client IP at the edge; implement tiered body limits; require secure cookies (`__Secure-`).
- **Context & Evidence:** Lab simulations proved role escalation prevention, CSRF mitigation, and rate limiter partitioning under Cloudflare topology.

---

## D-9a: Lead & Personal Data Protection (Editor Barrier)
- **Decision:** Enforce `authed(c, 'editor')` as the absolute minimum role permitted to view, export, or modify lead submissions, RMA records, job applications, and lead analytics.
- **Context & Evidence:** Verified in row 29 of `docs/04-ADMIN-CMS-SPEC.md`. Restricts Personally Identifiable Information (PII) from `viewer` and `member` roles.

---

## D-10: Pin PostgreSQL 18 in Every Environment
- **Decision:** Pin PostgreSQL 18 (`postgres:18-alpine`) across all environments, CI services, and Compose profiles.
- **Context & Evidence:** PostgreSQL 16 fails partial index predicates on enum casts (`42P17` / `55P04`). PostgreSQL 18 is verified to run all migrations with per-file transactions and supports modern features for a 5-year support window.

---

## D-11: Edge Security & Host Firewall
- **Status:** Accepted, not implemented (Target: Phase F)
- **Decision:** Cloudflare "Full (strict)" SSL with Origin CA certificate; Authenticated Origin Pulls (AOP); host firewall restricting ports 80/443 exclusively to Cloudflare's 22 published IP ranges; API port 8787 bound to `127.0.0.1` and never exposed externally.
- **Context & Evidence:** Defends against origin bypass attacks and client IP spoofing.

---

## D-12: Production Observability Stack
- **Status:** Accepted, not implemented (Target: Phase F)
- **Decision:** Structured JSON logging (Pino) to stdout; Sentry error tracking for API, Web, and Admin; Prometheus health metrics on private network; external uptime monitoring on `/api/v1/health`.
- **Context & Evidence:** Fulfills audit finding NTF-58, ensuring operational visibility, alerting, and rapid MTTR.
