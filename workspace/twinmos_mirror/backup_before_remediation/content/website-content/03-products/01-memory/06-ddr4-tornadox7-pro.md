## Performance Advantage

### CL16 vs CL22: Why Latency Matters

CAS Latency (CL) measures the number of clock cycles between a read command and data availability. At 3200MHz, each clock cycle is 0.625 nanoseconds. The difference between CL16 and CL22 is:

- **CL16**: 16 × 0.625ns = **10.0 nanoseconds**
- **CL22**: 22 × 0.625ns = **13.75 nanoseconds**

This 3.75ns improvement directly impacts:

| Application | CL22 Baseline | CL16 Improvement |
|-------------|---------------|------------------|
| **Gaming (CPU-bound)** | Baseline | 5–15% FPS improvement |
| **Spreadsheet recalculation** | Baseline | 10–20% faster |
| **Database queries** | Baseline | 8–15% faster |
| **Code compilation** | Baseline | 5–10% faster |
| **Application switching** | Baseline | Snappier response |

### Real-World Gaming Impact

Tighter timings reduce frame-time variance, leading to smoother gameplay in titles sensitive to memory latency:

- **CS2 / Valorant**: Reduced input lag and more consistent frame delivery
- **Strategy games** (Total War, Civilization): Faster turn processing and AI calculations
- **Simulation games** (Microsoft Flight Simulator, Cities: Skylines): Smoother simulation updates
- **Open-world RPGs** (Elden Ring, Baldur's Gate 3): Reduced stuttering in asset-dense areas

## Dual-Channel Configuration

For optimal performance, install TornadoX7 Pro modules in matched pairs to enable dual-channel mode. Dual-channel operation doubles the effective memory bandwidth, which is critical for integrated graphics performance and CPU-intensive applications.

| Configuration | Total Capacity | Channel Mode | Use Case |
|---------------|----------------|--------------|----------|
| 1× 8GB | 8GB | Single | Basic office, budget builds |
| 2× 8GB | 16GB | Dual | Gaming, mainstream use |
| 1× 16GB | 16GB | Single | Future upgrade path |
| 2× 16GB | 32GB | Dual | Content creation, development |
| 4× 16GB | 64GB | Dual (2 per channel) | Heavy workstations, VMs |

**Note**: For best stability, use matched pairs from the same batch. TornadoX7 Pro modules are tested in pairs at the factory.

## XMP 2.0 Profile

TornadoX7 Pro modules ship with a pre-programmed Intel XMP 2.0 profile:

| Parameter | XMP Profile | JEDEC Default |
|-----------|-------------|---------------|
| Speed | 3200MHz | 2133MHz |
| Timings | 16-18-18-36 | 15-15-15-36 |
| Voltage | 1.35V | 1.2V |

**Enabling XMP**: Enter BIOS setup (DEL/F2 during boot), navigate to the AI Overclocking or memory settings section, select XMP Profile 1, save and exit.

## Compatibility

TornadoX7 Pro modules are compatible with all DDR4-enabled desktop motherboards that support 3200MHz XMP profiles:

### Intel Platforms
- 100-series, 200-series, 300-series, 400-series, 500-series chipsets
- Core i3/i5/i7/i9 6th Gen through 11th Gen

### AMD Platforms
- 300-series, 400-series, 500-series AM4 chipsets
- Ryzen 1000 through Ryzen 5000 series

**Important**: XMP must be enabled in BIOS to reach 3200MHz CL16. Without XMP, modules will run at JEDEC default (2133MHz).
