# Accessibility Statement

> **Version 2.0 — Last Reviewed 2026-04-30**

TwinMOS Technologies is committed to ensuring digital accessibility for all users, including people with disabilities. We continually work to improve the user experience across our digital properties and strive to apply the latest accessibility standards.

## 1. Our Commitment

TwinMOS believes that access to information and digital services is a fundamental right. We are committed to providing a website experience that is:

- **Perceivable** — Information and interface elements are presented in ways all users can perceive
- **Operable** — All interface components and navigation are fully operable without a mouse
- **Understandable** — Information and operation of the interface are clear and predictable
- **Robust** — Content is reliably interpreted by a wide variety of assistive technologies, including current and future user agents

## 2. Conformance Status

We target conformance with **WCAG 2.2 Level AA**, published by the World Wide Web Consortium (W3C) in October 2023. WCAG 2.2 builds on WCAG 2.1 by addressing additional success criteria for mobile users, users with cognitive disabilities, and users with low vision.

Our website is designed to meet or exceed the following standards:
- **WCAG 2.2 Level A and AA** — Core international accessibility standard
- **EN 301 549** — European harmonized standard for ICT accessibility, referenced by both the EU Web Accessibility Directive (2016/2102) and the **European Accessibility Act (EAA, Directive 2019/882)** which took effect on **28 June 2025** for products and services in the EU

## 3. Accessibility Measures We Implement

### 3.1 Design & Structure
- Semantic HTML5 markup with correct heading hierarchy (H1–H6)
- ARIA (Accessible Rich Internet Applications) roles, labels, and descriptions where appropriate
- Sufficient color contrast ratios (minimum 4.5:1 for normal text, 3:1 for large text per WCAG 2.2 AA)
- Visible focus indicators on all interactive elements (meeting the enhanced WCAG 2.2 criteria for focus appearance)
- Consistent navigation landmarks and skip-to-main-content links

### 3.2 Images & Media
- Descriptive alternative text (alt text) for all informative images
- Captions and transcripts for video and audio content
- Complex images (charts, diagrams) accompanied by text descriptions or data tables

### 3.3 Keyboard & Motor Accessibility
- Full keyboard operability for all interactive elements, including navigation, forms, and custom widgets
- No keyboard traps — users can navigate to and away from all components using only a keyboard
- Logical and intuitive tab order matching visual layout
- No actions that require simultaneous or time-limited input (drag-and-drop alternatives provided)

### 3.4 Forms & Interactive Elements
- All form fields have visible, meaningful labels and error descriptions
- Error identification messages describe the nature of the error and how to correct it
- Form validation feedback is programmatically associated with the relevant field (accessible to screen readers)
- Redundant Entry: Users are not required to re-enter information already provided in the same session (WCAG 2.2 SC 3.3.7)

### 3.5 Cognitive Accessibility
- Clear, plain language used throughout the site
- Consistent navigation patterns across pages
- No content that flashes more than three times per second
- Help information available contextually throughout complex processes (WCAG 2.2 SC 3.3.5)

### 3.6 Mobile Accessibility
- Responsive design that adapts to screen sizes from 320px upward
- Touch target sizes meet minimum requirements (at least 24×24 CSS pixels, per WCAG 2.2 SC 2.5.8)
- Content does not require pointer precision or specific device orientation for essential functionality

## 4. Testing Approach

We use a combination of automated and manual testing methods to evaluate accessibility:

- **Automated scanning:** Regular scans using industry-standard accessibility testing tools
- **Manual testing:** Keyboard-only navigation review, logical reading order, and focus management checks
- **Screen reader testing:** Testing with NVDA (Windows), JAWS (Windows), and VoiceOver (macOS/iOS)
- **Mobile testing:** Testing on Android with TalkBack and iOS with VoiceOver
- **Color contrast checking:** Verified against WCAG 2.2 contrast ratio requirements

## 5. Known Limitations

Despite our efforts, some content may not fully meet WCAG 2.2 Level AA:

| Area | Known Limitation | Status |
|---|---|---|
| Legacy PDF documents | Older product datasheets and documentation may not be fully tagged for screen readers | Under remediation — new documents published to accessible standard |
| Third-party embedded content | Videos, maps, or widgets from third-party providers may not fully conform | We request accessible versions from providers; alternatives provided where possible |
| Complex data tables | Some technical specification tables may require improvement in header association | Being reviewed and updated progressively |

We are actively working to remediate these limitations. Where an accessible alternative is not yet available, please contact us and we will provide the information in an accessible format.

## 6. Assistive Technology Compatibility

Our website is designed to be compatible with the following assistive technologies:
- Screen readers: NVDA, JAWS, VoiceOver (macOS/iOS), TalkBack (Android)
- Screen magnification: Windows Magnifier, ZoomText, browser zoom up to 400%
- Switch access and alternative input devices
- Browser accessibility features (high-contrast mode, reduced motion)
- Voice control software: Dragon NaturallySpeaking, Voice Control (macOS/iOS)
