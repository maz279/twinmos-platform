## 1. Status Notice

> **This document is a placeholder for Phase 4 (post-launch).**
>
> GraphQL is **not enabled** in Phase 1, Phase 2, or Phase 3 of the TwinMOS website project.
> The REST API (documented in [TwinMOSWebsiteAPISpecificationOpenAPI.yaml](TwinMOSWebsiteAPISpecificationOpenAPI.yaml)) is the primary and only API interface for all current phases.
>
> GraphQL will be evaluated for Phase 4 if complex data-fetching needs arise (e.g., partner portal queries across multiple related collections) that the REST API handles inefficiently.

---

## 2. Rationale for Deferral

| Consideration | Assessment |
|--------------|-----------|
| Current API consumers | Astro static build (REST/JSON), CRM webhook (REST), ERP sync (REST) |
| REST adequacy | REST + sparse fieldsets (`?populate=...&fields=...`) covers all current use cases |
| GraphQL overhead | Additional dependency (`@strapi/plugin-graphql`), schema maintenance, n+1 query risk |
| Team size | 2-developer team; REST simpler to maintain |
| Phase 3 commerce | Medusa.js has its own Storefront API (REST); no GraphQL gap identified |

## 3. Future GraphQL Implementation Plan

If GraphQL is enabled in Phase 4, implementation will use **Strapi v5 GraphQL Plugin** (`@strapi/plugin-graphql`).

### 3.1 Enabling the Plugin

```bash
npm install @strapi/plugin-graphql
```

**`config/plugins.ts`:**
```typescript
export default {
  graphql: {
    config: {
      endpoint: '/graphql',
      shadowCRUD: true,           // Auto-generates types from Strapi schema
      playgroundAlways: false,    // Disable playground in production
      depthLimit: 7,              // Prevent deeply-nested abuse
      amountLimit: 100,           // Max items per query
      apolloServer: {
        tracing: false,
      },
    },
  },
};
```

### 3.2 Draft Schema Outline

```graphql
# Auto-generated by Strapi GraphQL plugin (shadowCRUD)

type Query {
  # Products
  product(id: ID!): ProductEntityResponse
  products(
    filters: ProductFiltersInput
    pagination: PaginationArg
    sort: [String]
    publicationState: PublicationState
    locale: I18NLocaleCode
  ): ProductEntityResponseCollection

  # Categories
  category(id: ID!): CategoryEntityResponse
  categories(
    filters: CategoryFiltersInput
    pagination: PaginationArg
    sort: [String]
  ): CategoryEntityResponseCollection

  # Brands
  brand(id: ID!): BrandEntityResponse
  brands(
    filters: BrandFiltersInput
    pagination: PaginationArg
    sort: [String]
  ): BrandEntityResponseCollection

  # Content
  newsArticle(id: ID!): NewsArticleEntityResponse
  newsArticles(
    filters: NewsArticleFiltersInput
    pagination: PaginationArg
    sort: [String]
    publicationState: PublicationState
    locale: I18NLocaleCode
  ): NewsArticleEntityResponseCollection

  # Distribution
  distributors(
    filters: DistributorFiltersInput
    pagination: PaginationArg
    sort: [String]
  ): DistributorEntityResponseCollection
}

type Mutation {
  # Form submissions
  createFormSubmission(data: FormSubmissionInput!): FormSubmissionEntityResponse

  # Warranty
  createWarrantyRegistration(data: WarrantyRegistrationInput!): WarrantyRegistrationEntityResponse
}

# Core entity types (examples)
type Product {
  id: ID!
  documentId: String!
  name: String!
  slug: String!
  partNumber: String
  category: CategoryEntityResponse
  brand: BrandEntityResponse
  specValues: [SpecValue]
  images: [UploadFile]
  publishedAt: DateTime
  locale: String
  localizations: ProductRelationResponseCollection
}

type Category {
  id: ID!
  name: String!
  slug: String!
  parentCategory: CategoryEntityResponse
  products: ProductRelationResponseCollection
}

type Brand {
  id: ID!
  name: String!
  slug: String!
  logo: UploadFile
}

# Pagination
type Pagination {
  total: Int!
  page: Int!
  pageSize: Int!
  pageCount: Int!
}

type ResponseCollectionMeta {
  pagination: Pagination!
}

# Enums
enum PublicationState {
  LIVE
  PREVIEW
}

# Scalars
scalar DateTime
scalar JSON
scalar Upload
```

### 3.3 Authentication

GraphQL will use the same **JWT Bearer authentication** as the REST API:

```
Authorization: Bearer {accessToken}
```

Role-based access in GraphQL will mirror Strapi RBAC permissions.

### 3.4 Rate Limiting for GraphQL

GraphQL introspection will be disabled in production. Custom query depth and complexity limits:
- Max depth: 7 levels
- Max complexity: 100 (estimated field count)
- Rate limit: 60 queries/minute (same as REST search endpoint)

## 4. Decision Gate

Before enabling GraphQL in Phase 4, the following questions must be answered:

1. Is there a concrete frontend or partner API use case that REST cannot efficiently serve?
2. Can the engineering team maintain a GraphQL schema alongside the REST API?
3. Is the Strapi v5 GraphQL plugin actively maintained and compatible with the project's Strapi version?
4. Have the security implications (introspection, batch attacks, complexity attacks) been reviewed?

If all answers are yes, proceed with enabling the plugin and expanding this document to full specification status.
