## 1. Purpose and Scope

This guide defines the editorial standards for all written content published on the TwinMOS corporate website (`twinmos.com`). It applies to:

- Web page copy (all 16 content sections)
- Product descriptions and specifications
- Knowledge Base (KB) articles
- Buying guides and Learn Hub articles
- News, press releases, and event pages
- Support documentation
- Legal and compliance pages
- Regional and localised content (English source)
- UI microcopy (buttons, labels, tooltips, error messages)

All contributors — internal marketing staff, product managers, regional content owners, and external copywriters — must follow these standards. Translators must follow the companion [Translation Memory & Glossary](../F.4%20-%20Localization/TwinMOSWebsiteTranslationMemoryGlossary.md) document for locale-specific conventions.

### 3.2 Capacity Formatting

- Use GB for gigabyte, TB for terabyte — always uppercase, no period.
- Write as: **8 GB**, **16 GB**, **32 GB**, **64 GB**, **128 GB**, **256 GB**, **512 GB**, **1 TB**, **2 TB** — always with a space between number and unit.
- In product titles (H1, meta title), omit the space for compactness: **32GB**, **1TB** (follows industry convention in titles).
- Body copy: always use space: "The 32 GB kit includes two 16 GB modules."

### 3.3 Speed Formatting

- RAM speeds: **4800 MHz**, **5600 MHz**, **6000 MHz** — space between number and MHz.
- Transfer speeds: **7 GB/s**, **3.5 GB/s** — space between number and unit.
- In product titles: **6000MHz** (no space).

## 4. Grammar and Punctuation

### 4.1 English Variant

Use **British English** for all website content.

| British | American (Do Not Use) |
|---------|----------------------|
| optimise | optimize |
| colour | color |
| recognised | recognized |
| centre | center |
| licence (noun) | license (noun) |
| authorised | authorized |
| programme | program (except for software: "software program" is acceptable) |

Exception: technical product specifications, chip/standard names (e.g., "Intel® XMP 3.0") retain their original American-English spellings as they are proper names.

### 4.2 Oxford Comma

Use the Oxford (serial) comma before the final item in a list of three or more:
- Correct: "The kit includes two modules, a heatspreader, and an installation guide."
- Incorrect: "The kit includes two modules, a heatspreader and an installation guide."

### 4.3 Em Dash (—)

Use the em dash (—) with no spaces on either side for parenthetical emphasis in body copy:
- Correct: "TwinMOS—founded in 1998—has shipped memory to 93 countries."
- Incorrect: "TwinMOS -- founded in 1998 -- has shipped memory to 93 countries."
- Incorrect: "TwinMOS - founded in 1998 - has shipped memory to 93 countries."

Use the en dash (–) for ranges: "4800–6000 MHz", "2022–2026".

### 4.4 Hyphenation

- Hyphenate compound modifiers before a noun: "high-speed memory", "five-year warranty", "on-die ECC".
- Do not hyphenate when the modifier follows the noun: "memory that is high speed", "warranty of five years".
- Do not hyphenate product names even when used as modifiers: "CoreX Pro Gen 5 performance" (not "CoreX-Pro-Gen-5 performance").

### 4.5 Apostrophes

- Possessive of singular ending in s: "TwinMOS's products" (not "TwinMOS' products").
- Never use apostrophes for plurals: "SSDs" (not "SSD's"), "SKUs" (not "SKU's").

### 4.6 Quotation Marks

Use double quotation marks for direct quotes: "Engineered for performance."
Use single quotation marks for quotes within quotes or technical/code values in running text.

### 4.7 Ellipsis

Use a single Unicode ellipsis character (…) rather than three periods (...).

## 5. Numbers, Measurements, and Technical Values

### 5.1 General Number Rules

- Spell out numbers one through nine in body copy; use digits for 10 and above.
- Exception: always use digits for measurements, speeds, capacities, counts in spec tables.
- Use a comma as the thousands separator: 1,000; 93,000; 1,500,000.
- Use a period as the decimal separator: 3.5 GB/s, 4.8 W.

### 5.2 Performance Specifications

| Value Type | Format | Example |
|-----------|--------|---------|
| RAM speed | [Number] MHz | 6000 MHz |
| Read/write speed | [Number] GB/s or MB/s | 7 GB/s, 850 MB/s |
| Latency | CL[Number] | CL16 |
| Voltage | [Number] V | 1.1 V |
| Capacity (spec) | [Number] GB / TB | 32 GB, 1 TB |
| Capacity (title) | [Number]GB / TB | 32GB, 1TB |
| IOPS | [Number]K IOPS | 1,000K IOPS |
| TBW | [Number] TBW | 1,000 TBW |
| Warranty | [Number]-year | 5-year |
| Form factor | M.2 2280, M.2 2230 (always with period) | — |

### 5.3 Percentages

Use the % symbol with no space between the number and symbol: 99.9%, 4.5:1.

### 5.4 Temperatures

Use °C for all product documentation (do not use °F unless the page explicitly serves a US audience): "Operating temperature: 0–70 °C."

### 5.5 Dimensions and Weight

- Dimensions: [W] × [D] × [H] mm — use the multiplication sign (×), not the letter x.
- Weight: [number] g (grams) or kg.
- Always use metric units as primary; imperial in parentheses only when explicitly required.

## 6. Date and Time Formatting

### 6.1 Standard Date Format

- Long form: 1 May 2026 (day, written-out month, four-digit year — no ordinal suffix)
- Short form (tables, metadata): 2026-05-01 (ISO 8601)
- Do not use MM/DD/YYYY format (this is American and ambiguous)
- Do not use ordinal suffixes: "1st", "2nd", "3rd" in formal content (acceptable in marketing copy)

### 6.2 Times

- Use 24-hour time for technical documentation: 09:00, 14:30, 23:59 UTC
- Use 12-hour time for consumer-facing event times: 9:00 AM, 2:30 PM GST
- Always state time zone: GST, IST, UTC, BST — spell out on first mention: Gulf Standard Time (GST)

### 6.3 Date Ranges

- Use an en dash (–) without spaces for date ranges: "14–18 October 2026"
- For spans crossing years: "October 2025–March 2026"

## 7. Heading Hierarchy

### 7.1 Rules

- **One H1 per page** — the page title, matching or closely reflecting the meta title.
- H2 for major content sections (Features, Specifications, Compatibility, FAQ, Related Products).
- H3 for subsections within an H2 section.
- H4 for rare nested subsections (use sparingly; prefer bullet points instead).
- Never skip heading levels (e.g., do not jump from H2 to H4).
- Headings must be descriptive and keyword-informed — avoid generic headings like "Overview" alone; prefer "DDR5 Memory Overview" or "VOLTX DDR5 Features".

### 7.2 Heading Capitalisation

- Use **title case** for H1 and H2 headings.
- Use **sentence case** for H3 and below.
- Title case rules: capitalise the first word, last word, and all major words; do not capitalise articles (a, an, the), short prepositions (of, in, on, at), or conjunctions (and, but, or) unless they are the first word.

### 7.3 Examples

```
H1: VOLTX DDR5 U-DIMM — High-Performance Desktop Memory
H2: Key Features
H3: On-die ECC for data integrity
H2: Technical Specifications
H3: DDR5 speed and latency
H2: Compatibility
H3: Intel LGA 1700 (Alder Lake, Raptor Lake, Arrow Lake)
H2: Frequently Asked Questions
```

## 8. Lists and Tables

### 8.1 Bullet Lists

- Use bullet lists for unordered items where sequence does not matter.
- Use numbered lists for sequential steps (installation guides, troubleshooting steps).
- Each list item: begins with a capital letter; ends without a period unless it is a full sentence.
- Parallel construction required: all items in a list must use the same grammatical form.
- Do not use more than two levels of nesting.

### 8.2 Tables

- Use tables for specifications, comparison data, and structured reference material.
- Every table must have a header row.
- Align numeric columns right; align text columns left.
- Include a table caption (above the table) when the table is not self-explanatory from surrounding context.

**Specification table example:**

| Specification | Value |
|--------------|-------|
| Form Factor | U-DIMM |
| Capacity | 16 GB / 32 GB / 64 GB |
| Speed | 6000 MHz |
| Latency | CL40-40-40-80 |
| Voltage | 1.35 V |
| Standard | JEDEC / Intel XMP 3.0 / AMD EXPO |
| Warranty | 5 years |

## 9. Abbreviations and Acronyms

### 9.1 First-Use Rule

Spell out the full term on first use in a page or article, followed by the abbreviation in parentheses. Use the abbreviation alone thereafter.

- "Random Access Memory (RAM)… The RAM in your PC determines…"
- "Non-Volatile Memory Express (NVMe)… NVMe drives outperform SATA…"

### 9.2 Abbreviations That Do Not Need Expansion

These are widely understood in the target audience and do not require first-use expansion on product and category pages:
DDR5, DDR4, SSD, USB, RGB, PCIe, M.2, SATA, RAM, CPU, GPU, MB, GB, TB, MHz, GHz, V, W.

They do require expansion on non-technical pages targeting general consumers (About, News, regional landing pages).

### 9.3 Company and Standards Body Abbreviations

Expand on first use in formal and legal documents:
- "Joint Electron Device Engineering Council (JEDEC)"
- "Restriction of Hazardous Substances (RoHS)"
- "CE (Conformité Européenne)"

## 10. Link Text Standards

### 10.1 Rules

- Link text must describe the destination: use descriptive anchor text that makes sense out of context (for accessibility and SEO).
- Never use generic phrases as link text: "click here", "read more", "here", "link", "this page".
- Do not repeat the same link text pointing to different destinations on the same page.

### 10.2 Correct Examples

| Correct | Incorrect |
|---------|-----------|
| [VOLTX DDR5 6000MHz 32GB specifications](/products/memory/voltx-ddr5-6000mhz-32gb/) | [Click here](/products/memory/voltx-ddr5-6000mhz-32gb/) |
| [Submit an RMA request](/support/rma/submit/) | [Submit here](/support/rma/submit/) |
| [DDR5 vs DDR4: Complete buying guide](/learn/buying-guide/ddr5-vs-ddr4/) | [Read more](/learn/buying-guide/ddr5-vs-ddr4/) |
| [TwinMOS warranty policy](/legal/warranty/) | [Learn more about our warranty](/legal/warranty/) ← vague |
| [Find authorised retailers in India](/regional/india/) | [India page](/regional/india/) |

### 10.3 External Links

- External links open in the same tab (no `target="_blank"`) except for documents (PDF, datasheet downloads).
- Downloadable files: indicate the file type and size in the link text: "Download VOLTX DDR5 Datasheet (PDF, 2.4 MB)."
- Do not use sponsored/affiliate links without a disclosure label.

## 11. Code and Technical Notation

### 11.1 Inline Code

Use backtick code formatting for: file names, command-line instructions, API endpoints, configuration values, CSS class names, and variable names in technical KB articles.

- Example: Run `firmware-update.exe` from the extracted folder.
- Example: Set `output: 'static'` in your Astro config.

### 11.2 Code Blocks

Use fenced code blocks (triple backtick with language identifier) for multi-line code:

```bash
# Flash firmware
./twinmos-flash --device /dev/sda --firmware voltx-fw-2.1.bin
```

### 11.3 Keyboard Shortcuts

Format keyboard shortcuts using angle brackets: press `Ctrl` + `Alt` + `Del`. Use the + sign with spaces on either side.

## 12. Image Alt Text

### 12.1 Rules

- Every `<img>` element must have a non-empty `alt` attribute.
- Alt text describes the content and purpose of the image, not "image of…" or "photo of…".
- For product images: include the product name, key spec, and colour/variant where relevant.
- For decorative images: use an empty alt attribute (`alt=""`).
- For charts and diagrams: alt text should summarise the key finding, not just the title.

### 12.2 Examples

| Image | Correct Alt Text |
|-------|-----------------|
| VOLTX DDR5 product photo | `VOLTX DDR5 6000MHz 32GB U-DIMM desktop memory module with black heatspreader` |
| Benchmark bar chart | `Bar chart showing VOLTX DDR5 6000MHz read speed of 89.3 GB/s vs competitor average of 74.2 GB/s` |
| TwinMOS logo | `TwinMOS Technologies logo` |
| Decorative hero gradient | `alt=""` |
| Installation diagram | `Step-by-step diagram showing how to install a DDR5 DIMM into a motherboard slot` |

## 13. Do-Not-Translate and Do-Not-Localise Terms

The following terms must appear in their original form across all locales. Translators must not translate, alter capitalisation, or transliterate these unless a Strapi-approved locale override exists.

### 13.1 Brand and Product Names (Always Preserve in Latin Script)

TwinMOS, VOLTX, CoreX Pro, CoreX, TornadoX7 Pro, TornadoX7, Thunder GX, Concord, Xtreme Pro, Xtreme, Alpha Pro, TW300, Hyper H2 Ultra, ELITE Drive Pro, ProDrive Ultra, Mobile Disk X3

### 13.2 Technology Standards and Protocols (Always Preserve)

DDR5, DDR4, DDR3, LPDDR5, NVMe, PCIe, SATA, M.2, JEDEC, XMP, EXPO, ECC, RGB, USB, USB-C, USB 3.2 Gen 2, HDMI, DisplayPort, Thunderbolt

### 13.3 Regulatory and Certification Marks (Always Preserve)

CE, UKCA, FCC, RoHS, REACH, EAC, ISO 9001:2015, BIS, WEEE, EPEAT, JEDEC

### 13.4 SKU / Part Numbers (Always Preserve)

All SKU codes (e.g., TMD5R600032G-U, TMSSD-CXP5-1TB) must be reproduced exactly including hyphenation and case.

## 15. File Naming and Slug Conventions

### 15.1 Content Files (Markdown)

Format: `{##}-{section-slug}/{##}-{file-slug}.md`
- Numbers are zero-padded to two digits.
- Use hyphens (not underscores) in slugs.
- All lowercase.
- Example: `03-products/01-memory-overview.md`

### 15.2 URL Slugs

- Lowercase, hyphen-separated, no trailing slash.
- Maximum 60 characters.
- Avoid stop words (a, the, and, of) unless necessary for meaning.
- Example: `/products/memory/voltx-ddr5-6000mhz-32gb/`

### 15.3 Image Files

See the companion [Image Asset Naming Convention](TwinMOSWebsiteImageAssetNaming_Convention.md) document.

### 15.4 Document References

Project documentation files follow: `TwinMOSWebsite{Section}_{Descriptor}.md`
- PascalCase with underscores between logical parts.
- No spaces in filenames.
